# Data Model: Live Stroke Preview

**Feature**: `005-live-stroke-preview`  
**Date**: 2026-05-18  
**Layer**: Client-side only (transient); server is a stateless relay

---

## Overview

This feature introduces a single new transient entity (`StrokePreview`) and a single new client-side data structure (`PreviewRegistry`). Neither is persisted on the server or added to the permanent operation history. All existing entities (`Operation`, room state) are unchanged.

---

## Entity: StrokePreview

A transient, non-persisted representation of an in-progress drawing or erasing action. Exists only in memory on the client.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `operationId` | `string` (UUID v4) | ✅ | Generated by the drawing client at pointer-down. Shared across all preview events and the eventual commit event for the same stroke, enabling correlation. |
| `userId` | `string` (UUID v4) | ✅ | Identity of the user drawing. Set from the session userId assigned at socket connect. |
| `type` | `'DRAW' \| 'ERASE'` | ✅ | Mirrors the `OP_TYPE` values from `shared/constants.js`. Determines how the overlay canvas renders the preview. |
| `points` | `Array<{ x: number, y: number }>` | ✅ | Accumulated virtual-coordinate points collected since pointer-down. Each event carries the **full array** to date (not a delta). Virtual coordinate space: `VIRTUAL_WIDTH × VIRTUAL_HEIGHT` (1920 × 1080). |
| `color` | `string` (CSS hex) | for DRAW | Active stroke color at the time of pointer-down. Constant for the duration of the stroke. |
| `brushSize` | `number` (virtual units) | for DRAW | Active brush width at the time of pointer-down. Constant for the duration of the stroke. |

**Validation rules**:
- `operationId` must be a non-empty string matching UUID v4 format on both client emit and server relay.
- `type` must be one of `OP_TYPE.DRAW` or `OP_TYPE.ERASE`; the server drops events with any other value.
- `points` must be a non-empty array; the server drops events where `points` is missing or not an array.
- `color` and `brushSize` are only required when `type === DRAW`. For `ERASE`, these fields may be absent.
- Server validates that `payload.userId === sessions.get(socket.id).userId`; mismatch causes a silent drop + warning log.

**Lifecycle**:
```
pointer-down        → StrokePreview created (operationId, type, points=[first point], color, brushSize)
pointer-move (×N)   → points array grows; throttled preview event emitted (≤1/30ms)
pointer-up          → draw:stroke commit emitted; StrokePreview removed from registry
pointer-cancel      → stroke:cancel emitted; StrokePreview removed from registry
pointer-leave       → point collection paused; preview remains visible
pointer-enter       → point collection resumes
canvas:cleared      → all StrokePreviews removed from registry (all users)
user:left received  → all StrokePreviews for that userId removed from registry
```

## Data Structure: PreviewRegistry

A per-client in-memory map maintained by the `usePreviewLayer` hook. Holds the latest known `StrokePreview` for every active in-progress stroke visible on this client.

```
PreviewRegistry: Map<string (operationId), StrokePreview>
```

**Invariants**:
- At most one entry per `operationId` at any time. A new preview event for an existing `operationId` replaces the previous entry (full-array approach means the latest event always supersedes earlier ones).
- The same registry holds both local (self) and remote (other users) in-progress strokes.
- The registry is cleared atomically when a `canvas:cleared` operation is processed.
- Remote previews for a disconnected user are cleared when `user:left` is received for that `userId`.

**Operations**:

| Operation | Trigger | Effect |
|-----------|---------|--------|
| `setPreview(preview)` | Local pointer-move; `stroke:preview:broadcast` received | Upsert entry keyed by `preview.operationId` |
| `removePreview(operationId)` | Local pointer-up / pointer-cancel; `stroke:cancel:broadcast` received; commit arrived for that ID | Delete entry by `operationId` |
| `clearAllPreviews()` | `canvas:cleared` received; `user:left` received (caller filters by userId before calling) | Clear all entries (or all entries for a given userId) |

## Rendering Model (Preview Layer)

The preview layer renders on a dedicated `<canvas>` element overlaid above the committed operations canvas. It is driven by the same RAF loop as the committed renderer but uses `previews` (the `PreviewRegistry` values) instead of `operations`.

| Rendering rule | Detail |
|----------------|--------|
| `type === DRAW` | Same `renderDraw` logic as committed ops: `strokeStyle = preview.color`, `lineWidth = preview.brushSize`, `lineCap/lineJoin = round` |
| `type === ERASE` | Same `renderErase` logic: `clearRect` boxes at each point scaled by erase radius |
| Opacity | Full opacity — identical appearance to committed strokes (FR-001, FR-004) |
| Z-order | Preview canvas is above committed canvas via CSS `z-index` |
| Clear policy | Preview canvas is cleared in full at the start of each dirty frame, then all current previews are repainted |

## Relationship to Existing Entities

```
Operation (committed, persisted in roomService)
  └── operationId: UUID     ← shared with StrokePreview during in-flight stroke

StrokePreview (transient, client-only)
  └── operationId: UUID     ← same ID as eventual Operation (for correlation)
  └── userId: UUID           ← matches Operation.userId once committed
  └── type/points/color/brushSize ← identical fields to Operation (subset)
```

The `StrokePreview` is a "shadow" of the future `Operation` that will replace it. Once the commit event arrives, the preview is removed and the committed `Operation` takes over rendering on the main canvas.

## New Constants (shared/constants.js additions)

```js
// Client → Server
EVENTS.STROKE_PREVIEW   = 'stroke:preview'
EVENTS.STROKE_CANCEL    = 'stroke:cancel'

// Server → Client
SERVER_EVENTS.STROKE_PREVIEW_BROADCAST  = 'stroke:preview:broadcast'
SERVER_EVENTS.STROKE_CANCEL_BROADCAST   = 'stroke:cancel:broadcast'
SERVER_EVENTS.USER_LEFT                 = 'user:left'
```

No new `OP_TYPE` values are added — previews reuse `OP_TYPE.DRAW` and `OP_TYPE.ERASE`.

## State Transitions Diagram

```
[IDLE]
  │
  │ pointer-down
  ▼
[IN_PROGRESS]  ←──────────── pointer-enter (resumes point collection)
  │  │
  │  │ pointer-leave
  │  ▼
  │ [PAUSED]  (preview visible, no new points)
  │
  │ pointer-up     → emit draw:stroke commit → remove from registry → [IDLE]
  │ pointer-cancel → emit stroke:cancel      → remove from registry → [IDLE]
  │ canvas:cleared                           → remove all previews  → [IDLE]
  └──────────────────────────────────────────────────────────────────────────
```
